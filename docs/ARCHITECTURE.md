# Star Arm 102 数字孪生平台运行架构

| 位置 | 负责什么 |
| --- | --- |
| 服务器静态网站 | 页面、3D 资源、界面交互、Ubuntu 安装包模板 |
| 客户浏览器 | 控制台 Web Serial、ACT 页面、本机 API 调用、当前网站安装包生成 |
| 客户 Ubuntu 后台 | 串口、原生相机、数据保存、校准、模型导入、训练及推理任务 |
| 独立 Python 环境 | LeRobot、PyTorch、策略加载和 GPU 计算；由第 2 步准备 |

本地源码启动时，网页和 API 同时由 `127.0.0.1:18765` 提供。服务器方式中，网页来自 HTTPS 网站，API 仍来自客户电脑 `127.0.0.1:18765`。

Ubuntu `.deb` 安装程序将后台放到 `/opt/star-arm-act`，注册桌面启动和登录自动启动。活动用户探测通过 `loginctl` 完成，用户会话由 `runuser` 启动；后台按桌面用户身份运行。数据写入用户目录，应用安装目录不存储客户示教数据。

网页下载时自动识别网站 origin，先验证模板 SHA256，再生成带该网站绑定信息的 `.deb`。后台只监听环回接口，并验证 Host 与已授权网站。公开健康探测只报告是否授权，不允许未授权网站运行机械臂命令或访问数据。

当前模型训练环境是 Python 虚拟环境，不使用 Docker。训练清单支持 CUDA / ROCm / XPU 安装来源，但是否可用必须通过本机自检。源码不打包 GPU 驱动、用户权重或整套训练环境。
