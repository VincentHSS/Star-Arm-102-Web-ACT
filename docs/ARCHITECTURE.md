# Star Arm 102 数字孪生平台运行架构

| 位置 | 负责什么 |
| --- | --- |
| 服务器静态网站 | 页面、3D 资源、浏览器执行引擎、Ubuntu 安装包模板；不运行模型 |
| 客户浏览器 | 控制台 Web Serial；纯网页 ACT 使用 WebGPU / Worker、浏览器双相机和串口直接执行；本机路线调用 API |
| 客户本机后台 | Ubuntu 串口 / V4L2 / 训练与执行；Windows COM / DirectShow / 已训练模型执行 |
| 独立 Python 环境 | LeRobot、PyTorch、策略加载和 GPU 计算；由第 2 步准备 |

纯网页 ACT 的模型和校准保存在当前网站的浏览器存储中，不上传服务器，不调用客户本机 Python API。模型转换由提供方训练端完成，客户端只加载网站引擎和模型。

在本机 LeRobot 路线中，本地源码启动时，网页和 API 同时由 `127.0.0.1:18765` 提供。服务器方式中，网页来自 HTTPS 网站，API 仍来自客户电脑 `127.0.0.1:18765`。

Ubuntu `.deb` 安装程序将后台放到 `/opt/star-arm-act`，注册桌面启动和登录自动启动。活动用户探测通过 `loginctl` 完成，用户会话由 `runuser` 启动；后台按桌面用户身份运行。数据写入用户目录，应用安装目录不存储客户示教数据。

网页下载时自动识别网站 origin，先验证模板 SHA256，再生成带该网站绑定信息的 `.deb`。后台只监听环回接口，并验证 Host 与已授权网站。公开健康探测只报告是否授权，不允许未授权网站运行机械臂命令或访问数据。

当前模型训练环境是 Python 虚拟环境，不使用 Docker。训练清单支持 CUDA / ROCm / XPU 安装来源，但是否可用必须通过本机自检。源码不打包 GPU 驱动、用户权重或整套训练环境。

Windows 使用源码启动脚本打开本机网页，第 2 步安装执行环境；使用服务器网页时，客户在本机确认页允许当前网站后，继续在原网页操作。Ubuntu 的首次组件安装使用 `.deb`，Windows 使用源码启动脚本。Windows 运行环境保持固定目录，已安装的虚拟环境不迁移；CUDA 或 CPU 以自检结果为准。
