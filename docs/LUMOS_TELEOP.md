# Touch R1 与 LumosTouch 遥操作

在 Ubuntu 上启动本地控制台，通过网页连接 Touch R1 主臂和 LumosTouch 从臂，再完成校准与遥操作。主臂使用浏览器 Web Serial；从臂通过本机 Lumos SDK 和 CAN 通信。此流程只允许配对的 Touch R1 控制真实 LumosTouch。

## 启动

适用环境为 **Ubuntu 22.04 / 24.04、x86-64、系统 Python 3.10～3.12**。使用 Chrome 或 Edge 打开本地控制台。

从 GitHub **Code → Download ZIP** 下载完整源码并解压，在源码目录启动 `start_ubuntu_lumos.sh`。如果文件管理器没有“在终端运行”选项，可以在该目录打开终端，仅运行这条启动命令：

```bash
bash start_ubuntu_lumos.sh
```

首次启动自动检查系统构建依赖、下载固定版本 Lumos SDK，并创建独立 Python 环境。系统缺少依赖时会请求 Ubuntu 安装授权；包管理器锁最多等待 300 秒，网络下载与 Python 依赖安装有限重试。首次联网准备和本地编译可能需要数分钟，实际取决于网络与电脑，请保留启动窗口；再次启动复用已准备的环境。

准备完成后自动打开 **http://127.0.0.1:18766/index.html**。该服务使用独立端口，已有 ACT 服务继续使用 18765。重复启动会检查版本、源码目录、源码内容和数据目录：一致时打开现有服务，不一致时显示正在使用的版本与目录，等待用户正常结束原任务后重启。

可选参数：

```bash
# 不自动打开浏览器
bash start_ubuntu_lumos.sh --no-browser

# 只读检查其他 CAN 接口；实际连接接口仍在网页选择
bash start_ubuntu_lumos.sh --can-interface can1

# 使用指定的本地服务数据目录
bash start_ubuntu_lumos.sh --state-dir /实际路径/lumos-data
```

## 网页操作

左侧遥操作面板按“连接 → 校准 → 运行”显示当前步骤。连接后收起已锁定的设备选项，六轴映射放在可展开设置中；校准完成后显示六轴目标及夹爪实际/目标开度。电机连接期间始终保留停止操作，停止后重新连接与校准。

1. 在控制台选择 **Leader 类型 → Touch R1**，通过浏览器的串口选择窗口连接对应主臂。
2. 在真实从臂中选择 **LumosTouch V3**，点击“检查本机组件”，核对 CAN 接口及显示的 SDK 夹爪类型与实体一致。确认后连接 Follower；此时 SDK 会使能从臂电机和夹爪，请提前确认从臂位置和周围空间。
3. 将两臂放到对应参考姿态，核对六轴映射、方向、增益及夹爪反向选项，再点击“记录参考姿态”。缓慢逐轴移动 Touch R1 采集使用范围，每轴至少覆盖 2°；采集期间 LumosTouch 不跟随。
4. 将 Touch R1 夹爪闭合并点击“记录夹爪闭合”，再张开并点击“记录夹爪张开”，保持端点姿态直到网页确认。两个端点的编码器读数需相差至少 2°，随后点击“完成校准”。
5. 核对六轴与夹爪目标预览，把两臂放回参考姿态，并对齐主从夹爪开度。网页要求实际夹爪与目标开度相差不超过 10%；确认后点击“开始”启动六轴与夹爪跟随。
6. 停止、断开设备或退出页面时结束控制；关闭本地服务时，在启动终端按 **Ctrl+C** 正常退出。

下载完成或打开网页本身不会连接 CAN 机械臂。Lumos SDK 只在网页明确连接从臂时创建机械臂实例。Touch R1 必须完整回读 **ID 0～5 六轴和 ID 6 夹爪**，七个通道共同参与遥操作；任一通道缺失或输入超时，都会停止机械臂和夹爪。

上游 URDF 的 0° 是装配姿态，不能代替实机编码器零位。当前校准只用于本次连接，不保存为可自动复用的硬件标定文件。停止、断开或输入超时会关闭 CAN 控制连接；重新连接后重新记录对应参考姿态、六轴范围及夹爪闭合/张开端点。

夹爪根据本次记录的两个原始角度端点换算为 0～100% 开度，0% 为闭合、100% 为张开；需要反向跟随时，在记录参考姿态前勾选“反转夹爪开合方向”。网页同时显示从臂实际反馈开度和目标开度。LumosTouch 三维夹爪按该比例映射模型行程，不能用画面中的长度代替真实夹爪行程测量；Touch R1 上游模型仅包含六个转动关节，其模型结构不限制实体夹爪参与控制。

## CAN 与系统权限

启动器和网页不会自动启用、停用或重配 CAN。启动时只执行接口状态读取，要求现场已准备好对应的 **1 Mbps CAN** 接口；如果接口不存在、未启用或波特率不同，会显示具体状态。

现场人员可以用以下只读命令检查：

```bash
ip -details link show can0
```

若不符合条件，请由设备提供方按当前适配器、驱动和接线完成配置，再回到网页连接。浏览器请求主臂串口授权时选择正确设备；如系统提示权限不足，按 Ubuntu 设备权限设置处理。

系统依赖包括 Python venv/开发头文件、编译工具、CMake、pkg-config、Eigen、yaml-cpp、Orocos KDL、TinyXML2、pybind11、OpenGL/GLib 运行库、iproute2 与 CA 证书。脚本使用 `/usr/bin/python3` 创建环境，不使用已激活的 Conda，不需要 Docker、PyTorch 或 LeRobot。请使用普通桌面用户启动；只有安装缺少的系统包时会单独请求授权。

## 文件与版本

默认目录：

| 用途 | 位置 |
| --- | --- |
| SDK 与独立 Python 环境 | `~/.cache/star-arm-102/lumos/python-3.x-04041254/` |
| SDK 源码根目录 | 上述目录中的 `startouch_sdk/` |
| SDK 原配置 | `startouch_sdk/src/config/robot_kinematics.yaml` |
| 本地服务数据 | `~/.local/share/star-arm-102/lumos/data/` |

设置了 `XDG_CACHE_HOME` 或 `XDG_DATA_HOME` 时使用对应目录。请保留 SDK 源码目录及其中 YAML；启动器通过 `STAR_ARM_LUMOS_SDK_ROOT` 将 SDK 根目录传给后台。不要把 YAML 单独移到 Python 包安装目录。

固定 SDK 的默认夹爪配置为 `TypeLJ`，还支持 `TypeFZ` 和 `TypeNex`。请使用设备提供方已核对的配置，不能仅凭 URDF 中的夹指长度选择类型。需要调整配置时，先停止并正常退出本机服务，由设备提供方更新上述 SDK 原配置，再重新启动、检查网页显示的类型。启动器保留已有配置，不自动修改夹爪类型；连接时关闭 SDK 的自动闭爪行为，校准与预览阶段不发送开合目标。

算法依据用户提供的 [Star Arm 102 → Lumos 遥操作项目](https://github.com/VincentHSS/stararm102-lumos-teleop/tree/c9922364)，对应六轴方向、相对参考姿态映射、滤波、限速和夹爪端点比例映射。SDK 固定为 [Lumos StarTouch SDK 提交 04041254](https://github.com/lumos-open/startouch_sdk/tree/040412542c0b6b6fd2bb6dd652c0de6c666631be)，其 Python 包声明为 MIT；安装时从官方仓库取得完整源码和运行库，本站源码及网页包不预置其 `.so`。下载归档需匹配启动器记录的 SHA-256 才会解压安装。

## 遇到问题

| 提示 | 处理方法 |
| --- | --- |
| 系统安装锁仍被占用 | 等待 Ubuntu 更新或其他安装完成，再运行启动器；不删除锁文件。 |
| SDK 下载失败 | 检查 GitHub 网络连接，恢复后重试。 |
| Python 依赖下载或构建失败 | 查看启动终端具体错误，恢复网络或补齐提示的系统依赖后重试。成功安装的文件会保留。 |
| 缺少 `robot_kinematics.yaml` | 恢复完整 SDK 源码目录；不能只保留安装后的 Python 模块。 |
| SDK 夹爪类型缺失或与实体不符 | 请设备提供方核对 SDK 配置中的 `gripper_control.type`，应为适用于当前夹爪的 `TypeFZ`、`TypeLJ` 或 `TypeNex`，不能凭名称猜选。核对后重新检查本机组件。 |
| Touch R1 六轴或夹爪回读缺失 | 核对主臂型号、接线和 ID 0～6 的回读；缺少 ID 6 时不能以六轴模式继续。 |
| 夹爪端点范围过小或开度未对齐 | 重新记录实际闭合、张开端点；开始前使主臂目标开度与 LumosTouch 实际反馈对齐。 |
| 18766 已有不同版本或目录 | 先在原网页停止遥操作、断开设备，再在原启动终端按 Ctrl+C 退出；然后启动当前版本。 |
| CAN 状态不满足要求 | 核对真实接口名、适配器驱动、接线以及 1 Mbps 配置，准备好后再连接。 |
| SDK 本机库导入失败 | 确认使用 x86-64 Ubuntu 22.04 / 24.04，并根据启动终端显示的缺失运行库处理。 |

自动测试只覆盖软件、模拟通信和资源加载；首次安装、硬件校准及真实遥操作仍需在目标 Ubuntu 和机械臂上验证。
