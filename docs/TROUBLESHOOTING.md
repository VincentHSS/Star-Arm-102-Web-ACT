# 常见问题

| 现象 | 排查方式 |
| --- | --- |
| Ubuntu 提示第 2 行或奇怪字符错误 | 使用仓库根目录 `start_ubuntu.sh`，以 `sh start_ubuntu.sh` 启动。不要拿 Windows `.bat` 在 Ubuntu 执行，不要保存为 CRLF 或带 BOM 的 shell 文件。 |
| Windows 双击后报 Python 不存在 | 安装 Python 3.10～3.12 并启用 PATH。窗口会保留具体错误。 |
| 启动后端口 18765 被占用 | v1.0.8 源码启动会检测并复用现有 ACT 服务；如果是其他软件占用，会明确提示。旧版 ACT 需先结束任务、正常关闭后重启。 |
| 下载组件后还是未连接 | `.deb` 仅下载并没有安装；必须用 Ubuntu 安装器安装并授权，然后回到网页。必要时重新登录桌面以触发自动启动。 |
| 安装器打不开或依赖未安装 | 确认系统为 Ubuntu 22.04 / 24.04，Python 3.10～3.12，系统软件源可用；用支持 `.deb` 的系统软件安装器打开。 |
| 网站与组件不匹配 | 从现在使用的网站重新下载并安装。每个安装包自动绑定生成它的网站地址。 |
| 安装包版本不一致 | 网站文件更新不完整或被旧缓存混用，同步替换安装包和全部页面脚本。 |
| 环境准备失败 | 查看第 2 步的具体错误、网络和 GPU 驱动。处理后点击重试，环境已经就绪时会复用。 |
| 环境一直显示“准备中”但后台已重启 | v1.0.8 会检测上次服务退出造成的中断，显示可重试提示；点击“重试准备”，保留已有模型和数据。 |
| 安装提示 dpkg 前端锁被占用 | 等 Ubuntu 更新完成，再打开同一个安装文件。源码启动自动等待 dpkg 锁最多 5 分钟；系统安装器的替代方式见 [Ubuntu 安装教程](UBUNTU.md#安装器提示-dpkg-前端锁被占用)。 |
| Windows 客户不想安装环境 | 打开网站的 `act-browser.html` 或第 4 步“Windows 网页直接执行”；使用转换好的网页模型，不用下载 Ubuntu 组件。 |
| 网页模型导入失败 | 确认是含 `web-act.json` 和 `model.onnx` 的包；原 PyTorch 检查点由提供方在第 3 步导出网页模型。 |
| 网页提示 WebGPU 不可用 | 使用桌面 Chrome / Edge、HTTPS，检查浏览器硬件加速和显卡驱动。 |
| 训练端导出网页模型报告接口不存在 | 更新训练端源码或 Ubuntu 组件到 v1.0.7；Windows 网页客户不安装该组件。 |
| 相机插上却未连接 | 插入不等于视频流已打开；确认后台已连接，在本机原生相机列表按模型角色选择两台不同设备并连接，确认没有其他应用占用相机。 |
| 第 1 步有画面，第 4 步没有 | 使用 v1.0.6 或更新网页；停止采集与推理后刷新。新版会复用双路浏览器预览，也保留原生相机连接。若标注“尚未接入推理”，准备本机环境后关闭相机、改选“本机原生”并重新连接。 |
| 两路相机反了 | 按模型特征与当前网页标签重新绑定；`wrist / world` 与 `up / front` 的机位不同。act-pick-v1.0.0 使用固定俯视 UP + 固定正面 FRONT，不能当作腕部相机。 |
| 校准等待有效角度 | 查看提示的关节与舵机 ID。多圈角度可能超过 ±180°，应按真实 SDK 读数和校准链路处理；不要直接裁剪数据伪造有效值。 |
| 模型导入要求完整模型包 | 使用工作台导出的完整包或已适配的完整发行包，包含配置、权重、处理器 JSON 与其引用的状态文件。任意原始 LeRobot checkpoint 不保证适配；不要添加空 `model.json` 绕过检查。 |
| 模型请求移动但机械臂不动 | 停止后确认同一台从臂、同一校准、正确串口、驱动写入与实际反馈。锁力成功不代表动作目标被执行。 |
| 切到第 4 步后从臂离线 | 步骤切换会释放串口；直接在第 4 步选择从臂串口，点击“连接从臂”。相机设置后返回第 4 步也要重新连接。 |
| 创建数据集无结果 | 查看“创建并锁定数据集”下方提示；标识需 3–48 位小写字母、数字或连字符，且不重复。检查本机服务。超时后先刷新列表核实是否已创建，再决定是否重试。 |
| 按钮一直处理或超时 | 请求和响应都有时间限制；等待提示，不连续重复点击写入、创建、导入等按钮。超时可能代表未能确认结果，不保证操作未执行，先核实当前状态。 |
| 控制台选完串口后长时间“正在连接” | 使用 v1.0.14 或更新网页。新版每轮统一等待并只补读缺失关节；查看日志中的打开串口和首次回读耗时，缺少反馈会列出具体 ID。更新网站后重新打开页面。 |
| 校准时无法切换页面 | 正在记录范围时先“完成并保存”或“取消记录”，再关闭或切换，避免丢失操作上下文。 |

Ubuntu 默认状态与日志目录为 `~/.local/share/star-arm-act/`，安装组件日志为该目录的 `runtime.log`；源码方式的启动错误显示在启动终端。分享错误时保留完整提示，但不要公开客户模型、校准和设备数据。

对应截图与完整操作：[图文快速上手](GETTING_STARTED.md) · [ACT 四步骤教程](ACT_GUIDE.md) · [Ubuntu 安装与启动](UBUNTU.md)

Windows 可使用本机源码网页，或启动服务并允许当前服务器网站连接后执行模型；训练使用 Ubuntu。安装准备失败时在第 2 步查看错误；CUDA 不可用可选择 CPU 重试。Windows 相机需允许桌面应用访问，模型执行串口为实际 COM 端口。

Ubuntu 提示 `dpkg` 前端锁被占用时，先等系统更新或其他安装结束，再重试。可用 `ps -p 报错中的PID -o pid,etime,comm,args` 查看进程；不要删除锁文件或未确认状态就强杀进程。依据 [Debian 官方锁说明](https://wiki.debian.org/Teams/Dpkg/FAQ#db-lock)。
