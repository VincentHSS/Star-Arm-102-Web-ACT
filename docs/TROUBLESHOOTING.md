# 常见问题

## 下载、安装与启动

| 现象 | 处理 |
| --- | --- |
| 对 `.deb` 执行 Bash，出现 `!<arch>` 语法错误 | 在下载目录运行 `sudo apt install ./实际文件名.deb`；它是 Ubuntu 安装文件 |
| 对 Lumos ZIP 不知道运行哪个入口 | 解压后在包目录运行 `bash start_ubuntu_lumos.sh`，完整步骤见 [Lumos 教程](LUMOS_TELEOP.md) |
| `--port` 不被识别或仍报 18766 | 运行到了根目录旧启动器或旧包；进入 `delivery/Star-Arm-102-Lumos-Ubuntu-v1.0.38/` |
| Lumos 端口被占用 | 客户本地版默认自动选空闲端口，也可用 `--port 18800`；地址以当前启动终端为准 |
| 网页没开，组件却已运行 | 安装的网站组件可在桌面登录时后台启动；先核对正在使用的入口，不同时连接同一设备 |
| 下载组件后网页仍未连接 | 完成系统安装授权，再返回下载组件的同一网站；首次 SDK 准备需要联网 |
| dpkg / APT 锁占用 | 等系统更新或原安装结束，再重试同一个安装文件；保留完整报错，无需反复下载 |
| 终端有 `(base)` | 交付启动器使用系统 Python；按包内脚本启动，不手动混用 Conda 环境 |
| Windows 找不到 Python | 完整平台源码方式需要 Python 3.10～3.12 及 PATH；纯网页执行方式不需要 Python |

## Lumos 与 CAN

| 现象 | 处理 |
| --- | --- |
| CAN 接口未启用或不是 1 Mbps | 停止并断开设备，在包目录运行 `sudo bash configure_can.sh can0`；实际接口不同则替换名称 |
| 查不到 CAN 接口 | 用 `ip -details link show type can` 检查系统识别结果，确认 USB-CAN 及驱动 |
| Touch R1 串口权限不足 | 核对串口选择、设备占用及当前用户的 dialout 权限；权限变更后重新登录 |
| 夹爪反馈无效或年龄为 `inf` | 当前 SDK 没有可接受的反馈；记录完整错误、当前入口和启动日志。先核对运行环境与配置，不将其直接等同于硬件损坏 |
| 已保存校准但不能直接开始 | 重新连接，回到参考姿态，检查并复用兼容校准；核对预览后仍需手动确认开始 |
| 设备、零位或夹爪型号有变化 | 重新校准，不沿用不匹配的旧数据 |

## 网站、ACT 与模型

| 现象 | 处理 |
| --- | --- |
| 三维模型慢或加载失败 | 完整上传 HTML、src、assets；确认文件大小写和资源响应，清理旧缓存后重试 |
| `.bin` 或 JS 请求返回 HTML | 修改静态服务器回退规则，缺失资源返回 404 |
| 网站说组件不属于当前域名 | 在当前网站重新下载并安装绑定该网站的组件，仅上传或刷新网页不能更新本机授权 |
| 第 4 步提示从臂未连接 | 在第 4 步重新选择串口并连接；上一步的连接状态不能直接沿用 |
| 相机有画面却提示未接入推理 | 原生执行需要本机原生双相机；按页面选择后端和角色，重新打开对应流 |
| 两路相机反了 | 按模型要求重新核对机位；`up/front` 与 `wrist/world` 不可混用 |
| 模型导入缺文件 | 导入包含配置、权重、处理器及引用文件的完整模型；纯网页方式使用提供方转换后的网页模型包 |
| 创建或导入请求超时 | 先查看列表和任务状态，核实是否已经完成，再决定重试 |
| 串口连接缺少反馈 | 查看日志中缺失的具体 ID、串口及波特率；锁力或模型显示不代表反馈完整 |
| 训练环境未就绪 | 在第 2 步查看实际失败阶段，处理网络或依赖错误后点击重试准备 |

Lumos 源码启动日志位于当前终端，校准数据默认在 `~/.local/share/star-arm-102/lumos/data`。ACT 安装组件状态与日志默认位于 `~/.local/share/star-arm-act/`。升级教程与交付文件不要求删除已有数据。
