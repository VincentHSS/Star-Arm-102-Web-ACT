# ACT 从采集到执行

## 1 · 设备与采集

选择主臂、从臂及两路相机，确认串口与设备绑定。`wrist` 是末端相机，`world` 是俯视相机；采集、训练和执行都要保持同一语义，不能仅按相机枚举顺序判断。

为当前从臂完成校准或导入原版 LeRobot 使用的同一份校准 JSON。记录各关节真实运动范围，确认有效后保存；校准记录中的暂时读数失败会持续重试并保留已有范围。校准解决模型归一化坐标与本台舵机范围的转换，原始角度数据不能直接替代其他模型的归一化输入。

创建并锁定数据集，设置任务名称、采集轮数和双相机参数，再开始示教。每轮结束后检查视频与 Action / State 曲线，接受有效轮次，删除无效轮次。数据集管理可以查看样本、同步和完整性情况。

切换 ACT 步骤时，平台会先停止当前采集或推理，再断开主从臂串口。已停止的采集轮次保留为待审核，返回采集步骤后继续审核；进入需要机械臂的步骤时重新连接设备。停止或串口释放失败时，页面保留在当前步骤并显示原因。

## 2 · 环境与训练

进入训练步骤会自动检查本机服务和训练环境。服务器网站首次使用需要安装 Ubuntu 组件，安装后自动接续环境准备；本地源码方式直接连接自身后台。

网页在独立 Python 虚拟环境中安装 LeRobot / PyTorch，并进行加速设备检查。环境失败时页面给出原因，处理后点击重试；已就绪的环境不会重复安装。选择通过检查的数据集和训练参数，启动训练并观察日志、进度和输出。

## 3 · 模型

导入完整 ACT 模型包，包含模型配置、权重与归一化信息。兼容导入逻辑包括发行包与 LeRobot 目录的识别、整理；单独一个权重文件不能补全输入特征或统计量。不要为了绕过检查而随便新建空的 `model.json`。

导入后检查模型的关节数量、相机特征、输入输出、帧率和运行条件。不同模型有不同的归一化统计，当前从臂校准与模型的坐标约定需要一致。

## 4 · 执行

选择导入的模型、本机从臂校准和两路原生相机，在本步骤的“从臂串口”区域选择设备并点击“连接从臂”；无需返回采集步骤连接。确认串口、相机及环境都已连接，再启动执行。当前实机执行走 Ubuntu 原生 FashionStar SDK / LeRobot 坐标转换与动作队列链路。

视频、Action / State 曲线和执行诊断用于观察模型输出与实际反馈。若模型请求移动而从臂无反馈移动，先停止执行并检查驱动写入、舵机反馈、校准和设备绑定；锁力状态本身不说明目标指令已经被正确发送。

首次在真实机械臂上验证时，先确认对应硬件的急停和停止按钮可用，并在工作空间内低风险任务验收。软件模拟测试不能证明实际串口、相机、GPU 和机械动作正常。
