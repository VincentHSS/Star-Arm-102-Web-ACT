# Windows 客户 · ACT 纯网页执行图文教程

这条路线只需要提供方的网站和**网页执行模型包**。客户不安装 Python、PyTorch、LeRobot、Docker 或 Ubuntu 组件，也不用运行启动脚本、本机服务或填写 API 地址。推理引擎随网站加载，图像、模型和关节计算都在客户浏览器内完成。

桌面 Chrome / Edge、HTTPS 网站、可用的 WebGPU 和被 Windows 识别的 USB 串口、双相机是运行条件。首次使用时，在浏览器中允许相机访问，并选择从臂串口。此权限由客户确认，网站不能替客户选择设备。

## 1. 打开正确入口

提供方可以直接将网站中的 **`act-browser.html`** 地址发给客户。Windows 从控制台点击 ACT 默认进入此路线。也可以进入原 ACT 工作台第 4 步，点击上方 **Windows 网页直接执行**。切换工作区时先释放设备，显示原有启动动画。

![Windows ACT 纯网页执行入口；未连接设备](images/windows-browser-execution.png)

截图为实际网页的未连接状态，没有展示模拟图像、机械臂运动或任务完成结果。左栏连接设备，中间同时显示双相机和 Action / State 曲线，右栏校验与执行；侧栏内容在栏内滚动。

## 2. 导入网页执行模型

1. 点击 **导入网页执行模型**，选择提供方给出的 ZIP。
2. 等待解包、SHA-256 校验和浏览器引擎加载。第一次下载网站的执行引擎、编译图形程序可能稍久，后续可复用浏览器缓存。
3. 确认模型名称、任务、相机角色和分辨率显示正确。
4. 模型会尝试保存在当前网站的浏览器存储中，下次打开可恢复。换网站、换浏览器、清理网站数据或存储空间不足时，需要重新导入。

网页模型 ZIP 应包含 `web-act.json` 和 `model.onnx`，不是原始 `.safetensors` 检查点。转换由提供方在训练端完成；不能将普通权重改名成 ONNX 或添加空清单来绕过检查。大小上限为 400 MB。

## 3. 连接双相机

1. 将两台相机连接到 Windows 电脑，点击 **检测浏览器相机**，按浏览器提示授权。
2. 根据模型定义给两路选择不同设备。例如 act-pick-v1.0.0 使用**固定俯视 UP + 固定正面 FRONT**。
3. 点击 **连接双相机**，观察两路真实画面。
4. 检查画面角度、光照、分辨率和实际 FPS。此入口的浏览器视频直接参与推理，不会显示旧本机模式的“仅浏览器预览”。

分辨率必须符合模型，不能用一个占位画面或过低的规格代替。一路 FPS 明显偏低时，关闭其他视频软件，检查相机模式和 USB 带宽；尽量将两台相机接到不同 USB 控制器。页面减少了逐帧更新统计文字的开销，但不能把相机实际提供的低帧率变成 30 FPS。

网页执行请求模型分辨率和 30 FPS，不自动降为 15 FPS。每路画面下方显示实际交付的帧率；“帧率偏低”表示低于 24 FPS，“画面停滞”表示超过 500 ms 未更新。若只连接相机、尚未执行就卡顿，请先检查这些数值；相机上报 30 FPS 不代表每秒实际交付了 30 帧。

## 4. 连接从臂与匹配校准

1. 点击 **选择并连接从臂**，在 Chrome / Edge 的窗口中选择真实从臂串口。
2. 等待七个舵机 ID 0–6 的有效反馈。连接时只读，不自动带动机械臂。
3. 使用归一化模型时，点击 **导入本台从臂校准 JSON**，选择同一台物理从臂的 LeRobot 校准文件。优先使用原版验证该模型时的那一份。
4. 使用角度模型时，不需要归一化校准；页面会明确显示。

校准是机械臂的设备参数，不是 Python 运行环境。不能用其他机械臂的文件或模拟范围代替，也不能省略坐标转换把归一化值当作角度。客户没有匹配文件时，应先由提供方在训练/设备配置流程中完成校准并交付。

## 5. 校验与执行

1. 点击 **校验设备与模型**。网页使用真实图像和关节反馈预热策略，检查输出和当前物理限位，校验不发送位置动作。
2. 检查提示和 Policy 延迟。推理速度不能可靠维持动作缓冲时会阻止执行。
3. 确认当前从臂、校准和双相机视角正确，扶稳机械臂、确认运动范围后勾选确认项。
4. 点击 **开始网页 ACT 执行**。启动采用原版 StaraiMotorsBus 的准备顺序：解除锁力、清圈、重新读取状态，再锁力并发送动作。
5. 点击 **停止执行并卸力**停止；关闭网页前先执行停止。切换工作区会等待串口释放。浏览器进入后台、画面失效、丢失关节反馈或动作缓冲耗尽时会停止发送新动作。

控制按 30 Hz 目标节拍读取时间索引动作块；预测在 Worker 中执行，不要求每 33 ms 重新计算完整模型。错过节拍时跳过过期动作，不把积压指令连续突发到机械臂。目标频率不等于所有电脑均已达到实测 30 Hz，实际情况看性能面板。

停止后，页面顶部保留具体原因。反馈超时会标出缺失的关节与舵机 ID；相机停滞、网页进入后台、推理超时和动作缓冲耗尽分别显示。右侧“当前状态”中的 **下载运行诊断** 可保存实际帧率、相机规格、推理与控制耗时，以及上次停止原因，便于提供方排查。Policy 延迟包含图像预处理和模型计算；时序曲线以 10 Hz 重绘，动作控制仍以 30 Hz 为目标。

## 6. 提供方训练完如何交付模型

1. 在 Ubuntu 按原 ACT 工作台流程准备环境、采集、训练并验证模型。
2. 到第 3 步，在对应模型卡片点击 **导出 Windows 网页模型**。
3. 网页自动准备转换依赖、生成模型并用三组输入比对原版策略输出；不兼容的处理器会报告错误，不会省略后直接执行。
4. 等待完成并下载 ZIP，将此包和网页入口发给客户。归一化模型同时提供客户当前从臂对应的校准文件。

提供方需使用包含此按钮和接口的新源码/Ubuntu 组件。旧后台报告接口不存在时先更新训练端，Windows 纯网页客户无需更新或安装后台。开发人员也可用 `tools/export_browser_act.py`；普通客户不用运行它。

此转换器目前支持七关节、两路同规格 RGB 图像、MEAN_STD 处理器的 ACT，坐标为角度或已适配的 StarAI 0.0.4 校准格式。图像规格与动作块长度固定在导出模型中。转换结果通过软件数值比对，不代替模型在目标物理从臂和场景中的验证。
