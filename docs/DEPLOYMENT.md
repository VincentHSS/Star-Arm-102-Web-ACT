# Star Arm 102 数字孪生平台 · 服务器发布

Star Arm 102 数字孪生平台包含 Star Arm 102 控制台和 ACT 工作台。PiPER Mate 是支持的硬件型号之一。

## 上传

1. 在 [Releases](https://github.com/VincentHSS/Star-Arm-102-Web-ACT/releases/latest) 下载 `Star-Arm-102-SERVER-UPLOAD-ONLY.zip` 并解压。
2. 把 `服务器网页` 文件夹**里面的所有内容**上传到网站根目录，保持目录结构。例如服务器上应直接存在 `index.html`、`act-workbench.html`、`src/`、`assets/`、`downloads/`。
3. 为网站启用 HTTPS，用 Chrome / Edge 访问首页。

服务器只需要静态网站托管，不需要 Python、GPU、Docker 或本机串口服务。没有额外的发布配置表，也不用填写域名。不要把源码仓库里的 `ai_service/`、测试或客户数据上传到公开站点。

如果从源码自行发布，上传 `Browser_SDK/` 里的全部内容，等同于交付 ZIP 的 `服务器网页`。代码改动后先按 [开发教程](DEVELOPMENT.md) 重新构建组件和网站包。

## 客户如何运行 ACT

客户电脑使用 Ubuntu。首次从网页第 2 步下载 Ubuntu 组件，网页自动绑定当前网站地址。客户通过 Ubuntu 软件安装器安装并授权后，回到网页即可继续环境准备；训练与执行仍在客户电脑上进行。

Ubuntu 组件是网页的一部分下载资源，不是第二个需要运营者单独配置的网站包。运营者上传一个网站文件夹即可。客户仍需完成首次系统安装授权，网页不能静默向尚未安装后台的电脑写入驱动或运行本机 Python。

以后进入网页会自动检测本机后台，已就绪的环境直接复用。组件只授权产生该安装包的网站地址。如果域名、协议或端口改变，应从新地址重新下载并安装组件。

## 托管要求与验收

- 保留 `downloads/act-runtime-template.deb`，网页用它生成绑定当前网站的安装包。
- JavaScript 必须以正常 JS 内容返回；静态资源不存在时不要把首页 HTML 冒充 JS 返回。
- 不要混用旧缓存文件，更新时同步替换 HTML、`src/` 和安装包。安装包与 `act-installer.js` 的 SHA256 必须一致。
- 如果添加网站安全策略，允许本机 `http://127.0.0.1:18765` 的连接和媒体资源；如浏览器询问本机网络访问权限，客户需允许。不能通过把后台开放到公网来解决此问题。
- 可以托管到域名子目录，保持相对路径。HTTPS 网站地址是自动识别的 origin，包含协议、域名和端口，不包含子目录。
- 验收首页 3D 显示、两页约 5 秒切换、第 2 步下载、Ubuntu 安装连接、设备选择、环境准备和模型执行。Ubuntu 实机验收需使用实际客户电脑。

配置与示教数据保留在客户电脑，不进入服务器静态目录。
